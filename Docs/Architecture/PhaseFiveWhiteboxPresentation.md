# 第五阶段设计草案：工业科幻白盒表现

日期：2026-10-10。状态：工业科幻白盒方向已批准，首批模型制作已完成；战斗表现、界面和实际关卡整合尚待实施。模型入口见 [制作约定](PhaseFiveModelProduction.md) 与 [模型检查报告](../Validation/PhaseFiveModelReport.md)。

用户确认现有玩法可以继续沿用，希望优化战斗反馈、画面、模型和地编；已选择“工业科幻，突出机械结构与重量感”。本阶段围绕现有双隘关卡提升表现。本文中的数值是制作起点，需要在实际镜头下调整。

## 设计目标

让玩家在普通战斗镜头下辨认建筑和敌人，感受到不同武器的节奏与重量，并看清能源状态和设施威胁。保持当前战斗规则、波次、建筑费用与占地、敌人导航和能源结算。

视觉关键词：灰白机械外壳、深色底座、青色能源、橙色敌方、清楚的硬表面轮廓、克制的灯光和短促反馈。

![工业科幻视觉概念](Images/PhaseFiveIndustrialWhiteboxConcept.png)

概念图使用内置 imagegen 生成，用于讨论形体、材质、配色和气氛，不是 Unity 实机。图中高密度岩石、表面零件及放大的反应堆应在白盒实施时简化。地形位置以现有地图为准，六种建筑仍采用当前定义的一格占地；概念图不作为尺寸或拓扑依据。完整生成提示保存在 `Images/PhaseFiveIndustrialWhiteboxConcept.prompt.md`。

## 当前画面依据

依据第四阶段完整游戏帧 `Logs/PhaseFour/editor-target-ui.png` 和当前表现源码：

- 地图主体在两侧较宽的界面之间显得偏小，建筑细节和反馈难以在全图观察时辨认。
- 建筑已有基础几何轮廓，三类敌人仍主要依靠体型和颜色区分。
- 射击主要表现为短线和范围圆环，敌人受击闪白，建筑用状态灯变色；炮塔后坐、独立命中表现和死亡过渡尚有提升空间。
- 深色地面与全图网格的视觉权重较高，岩体是连续方块，空间层次和方向标识较弱。
- 已使用 URP Lit/Unlit、方向光、池化表现及完整预存 UI。本阶段可沿现有结构扩展。

这些是对已保存画面与源码的观察，本轮未进入播放模式、修改场景或执行新的性能测试。

## 一、构图与画面层级

保留已确认的约 70° 正交俯视镜头。先扩大地图可用空间，再确定模型细节大小。以 1920×1080 为主要设计基准，同时检查 1280×720。

- 顶部保留紧凑的资金、波次、核心状态栏；底部集中放置建筑工具和战斗控制。
- 选中详情集中于右侧，未选中时收起，能源详细统计可展开。模型附近保留足够操作空间。
- 战场视口纵向争取使用约 80% 屏幕高度；实际地图投影仍受正交镜头、地图比例和窗口比例影响，不以视口面积代称有效地图面积。
- 默认构图能找到两处入口与核心；沿用滚轮缩放、中键拖动，可增加回到全图的按钮。镜头由玩家控制。
- 日光、环境填充和柔和阴影形成前后与上下关系。材质以哑光灰白、深灰金属为主，发光仅用于能源和状态部件。
- 地面亮度与友方外壳错开，敌人采用深色主体与少量暖色标识。默认关闭景深和运动模糊；发光强度以轮廓清楚为准。

建议的信息优先级为：敌人和受威胁设施 → 射击与命中 → 玩家选中对象 → 供电观察 → 地面装饰。

## 二、模型语言

每种单位先确定一个在俯视镜头中可见的主轮廓，再添加少量运动部件。顶面结构与体块比例优先于小螺丝、贴花和隐藏的底部结构。

| 对象 | 主要轮廓 | 运动与状态特征 |
| --- | --- | --- |
| 反应堆 | 矮宽基座、竖向能源舱、两侧散热体 | 舱内低速脉冲，储能变化主要由刻度和亮度范围表达 |
| 中继器 | 瘦高支柱、明显的环形顶部 | 实际发送时端口短闪，停机时灯暗 |
| 连射炮 | 紧凑转台、并列双炮管 | 小幅快速后坐，清晰而轻的射击节奏 |
| 重击炮 | 宽底座、粗长炮管、后坐滑轨 | 单次明显后坐、较慢复位，体现高冲击 |
| 范围炮 | 低矮环形发射器、分段外圈 | 环形部件短亮，命中点出现薄的扩散环 |
| 核心 | 方正装甲舱、四角护罩结构 | 护盾受击产生局部波纹，核心耐久受损另有明确反馈 |
| 普通敌人 | 紧凑的四足机械体 | 简单交替步态与轻微上下运动 |
| 快速敌人 | 低矮狭长的楔形滑行体 | 平稳贴地滑行、转向倾斜，尾部短促推进光 |
| 重装敌人 | 宽扁装甲车体、履带侧裙、前撞角 | 稳重推进、攻击时短促撞击与回收 |

建筑基座严格匹配现有占地。核心和反应堆通过轮廓、高度及局部发光获得辨识度；高度控制在不遮挡后方单位的范围。炮管、脚部与装饰轻微探出时仍以固定占地底框表达建造边界。

白盒模型采用少量倒角块体、棱柱与低边数圆柱。静止部件在制作时合并，转台、炮管、活动足等只保留必要分件。建议初始上限：单栋约 500—2000 三角面、单敌人约 200—800 三角面；实际开销同时检查材质数、渲染器数和特效，不能只凭面数承诺性能。

敌人首版用简单变换动画。外观碰撞体只服务选取或表现，敌人仍遵守现有逻辑位置、可重叠与攻击范围规则。

## 三、战斗反馈

每次攻击有可辨认的开火、命中和恢复节奏。现有攻击为即时命中，视觉沿同一已发生的战斗结果触发；射线、火花和后坐不改变伤害或能耗时刻。

| 行为 | 建议表现 | 初始时间范围 |
| --- | --- | --- |
| 连射炮开火 | 极短炮口闪光、细而短的曳光、炮管后坐 | 闪光 0.04—0.07 秒，后坐复位约 0.12 秒 |
| 重击炮开火 | 稍粗的短射线、强但局部的火花、明显炮管后坐 | 开火 0.08—0.12 秒，复位 0.25—0.35 秒 |
| 范围炮命中 | 命中点闪光、贴地薄环、少量碎片 | 扩散与消退合计约 0.25—0.4 秒 |
| 敌人受击 | 装甲局部短闪、轻微视觉震动 | 约 0.06—0.1 秒 |
| 敌人死亡 | 小型解体或塌落、少量碎片快速淡出 | 主体 0.15—0.3 秒，碎片约 0.6 秒 |
| 重装攻击设施 | 车体短促前压、接触点火花、随即回收 | 约 0.2—0.3 秒 |
| 建筑受损 | 受击点闪光；低耐久时稳定出现小型损坏标识 | 短反馈约 0.1 秒，严重损坏状态持续 |
| 建筑损毁 | 上部结构塌低、灯熄灭、短尘雾，保留清楚的残骸底座 | 转换约 0.25—0.5 秒 |
| 维修完成 | 结构立即恢复，短促绿色确认光 | 约 0.2 秒，付费与修复仍即时生效 |
| 核心受击 | 护盾局部波纹或装甲命中火花，区分护盾与耐久受损 | 约 0.15—0.3 秒 |

炮塔转台朝向当前目标；实际开火时对准该次射击快照。动画跟随权威目标，不因为等待转台而延迟开火。敌人死亡后的残影与碎片属于独立表现，不能继续被选为目标或阻挡移动。

范围攻击的圆环只表示这次攻击的范围，不表达持续伤害。攻击反馈使用出手时的目标位置，建筑移动之后旧效果留在原命中位置。游戏暂停冻结世界动作和特效时间，恢复后继续；重开清空表现。

战斗中同类短音效按距离和同时播放数量限制。三种炮塔分别采用短脆机械声、低沉单发冲击、短促脉冲声；能源告警只在状态变化时提醒。默认不常驻伤害数字，敌人血条在受伤或重点观察时显示；低血量和设施危急状态保留必要提示。

## 四、能源与状态的视觉分层

建议提供三种呈现状态，沿用同一个模拟世界，只改变可见信息：

| 呈现状态 | 主要显示 |
| --- | --- |
| 常态战斗 | 建筑/敌人、开火与命中、局部威胁和缺能提示；能源连线较淡，限制脉冲密度 |
| 能源观察 | 增强连接方向、实际流动和储能刻度；选中对象的直接连接最清楚 |
| 建造与移动 | 加强局部网格、实际占地、可连接范围和非法位置反馈 |

能源表现保持概念准确：预约用界面中的预约量表达，只有实际传输产生移动脉冲。脉冲可以合并为可读的流动表现，但不能让满缓存、已断链或未实际发送的线路持续假流动。

重装威胁按设施汇总，以暖色角标表达锁定，实际受击时短闪；搜索最后已知位置使用虚线十字。身份、几何形状和亮度共同表达状态，颜色是辅助。能源光采用青色，缺能警示采用琥珀色，实际受击采用短促橙红色。

储能条主要在选中与能源观察时显示。地面选择框、敌人威胁框和范围圈有不同形状；范围圈只在相关观察或建造时强化。

## 五、地编与环境

以现有 40×40 双隘地图、两处入口和 68 个岩体占地格为基础做视觉包装。

- 地面分为外围粗糙区域、通道过渡区域、基地工业平台，通过材质和宽松的分块体现区域，不在所有格子上画等强度网格。
- 岩体用少量不同轮廓的低矮岩块组合，底部边界准确落在不可通行区域；边缘增加克制的碎石与阴影，保持通道清楚。
- 两个入口使用不同编号、方向箭头和低矮警示标识，能快速对应波次提示。路面痕迹用于帮助辨认入口与通道，不暗示敌人只能沿绘制的线移动。
- 核心周边用地面拼装缝、边界灯和维护标识形成视觉中心，所有地面仍保持同一可通行高度。
- 大型山体、设备背景和环境轮廓放在地图外围；通行区的装饰不产生额外碰撞或遮住可选建筑。
- 地图边界和不可建造位置保持明确，避免出现可走的格子看起来被设备占据，或实际岩体看起来可以穿过。

概念图中的复杂崖壁和密集地面杂物在实施时简化。当前射击和能源不检查岩体遮挡，地编不额外表达“躲到石头后就不会受击”的掩体功能。

## 六、制作与工程范围

建议先制作阶段独立的场景、表现 Prefab 和材质，引用现有玩法定义。通过已有 `VisualRoot` 美术替换位置接入模型，UI 完整预存在场景或 Prefab。制作结果能够在编辑器直接预览和手工调整。

需要扩展的表现接口应围绕只读的射击、命中、死亡、维修及破坏结果组织；必要时提供有界的事件快照。消费一次后不会重复播放，跨多个逻辑步更新也不会因只读最后一帧而漏掉关键反馈。表现不得反向决定伤害、到货、目标或费用。

初始特效预算建议：同时最多 64 组短攻击/命中特效、128 个装饰碎片、128 个可见能源脉冲；重装目标标记继续按设施汇总。预算不足时优先保留核心、选中设施和重装攻击反馈，合并或省略次要表现。具体上限由本阶段实测调整，不限制真实攻击和运输数量。

复用现有 URP 与对象池。静态地编按区域组织，重复单位共享材质；动态特效不依赖每次临时创建材质或复杂刚体。所有新增模型、材质、动画数据及 Prefab 连同引用保存于工程。

## 七、建议制作顺序与验收

1. **静态构图样板**：完成相机视口、紧凑界面布局、一组建筑/敌人灰模和局部岩体/地面样板。以正常战斗镜头检查轮廓、比例、明暗及选取。
2. **战斗反馈样板**：接入三种炮塔开火、敌人受击/死亡、重装撞击、建筑受损/维修/残骸，以及能源观察表现。检查快慢节奏和结果一致性。
3. **整图整合**：铺设原双隘地图环境，统一材质和配色，完成声音与表现预算，保存可编辑场景及 Prefab。

验收关注：

- 1920×1080 和 1280×720 下能辨认六种建筑、三种敌人，减少对标签和颜色的依赖。
- 战斗、能源观察、建造三种状态都能明确选取目标，模型与装饰不遮住关键操作。
- 三种炮塔的开火节奏与命中效果可以区分；重装攻击与能源设施受损容易看到。
- 伤害、目标、能源实到、暂停、重开与表现一致，旧玩法回归保持通过。
- 用可见窗口记录普通战斗和 100 建筑/200 敌人短密集场景，分别检查帧时间、表现数量与可读性；后台运行和概念图不作为可见画面证据。
- 不重新进行已结束的第二阶段长时间验收，不执行哈希值校验。

初稿阶段产物为设计稿、概念图与提示记录。随后已按用户授权组织建筑、机械敌人、环境与技术美术三个专业子代理完成首批模型制作，由主负责人统一导入独立检视场景。现有第四阶段可玩场景保留；后续战斗表现、界面与观察模式及实际关卡整合仍由相应任务推进。

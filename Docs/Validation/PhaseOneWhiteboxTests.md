## 重要断言与误差边界

1. 每一个模拟步检查实际产生等于当前存量、在途量、消耗和各类损失之和；不将预约算作实际能量。
2. 终端检查“存量 + 最终有效到货承诺”不超过容量；中继检查“存量 + 下一跳预约”不超过容量。
3. 长期 4:2:1 测试先预热 100 步，再统计 1000 步实际到货；每个份额允许 2 个百分点误差，以覆盖批量和运输窗口边界。
4. 不同损耗测试的单跳保留率分别为 0.995 和 0.5，统计 1500 步，要求两端实际到货比在 1 的 3% 范围内。此用例能区分“按发出量平分”与已确认的“按有效到货量分配”。
5. 有限 70 点供给测试分别要求 40/20/10 与 10/40/20，没有放宽到只判断大小关系。
6. 超时边界测试在累计 29/30 步时提交修复，要求已经过去的最后一步仍被计入，不能靠当步重新发射逃避过期。
7. 拆分测试同时核对飞行片与留存片的实际访问序列和累计预算；已经滞留的留存片继续计时。
8. 确定性只覆盖同一运行环境、相同定义、相同种子和命令序列，不据此宣称跨平台位级一致。
9. 共同中继测试禁止源头直达终端：预热 200 步后统计 1200 步，4:2:1 份额允许 3 个百分点误差；同权重不同损耗的出口到货比允许 5% 误差。无损场景还要求最终到货达到中继额定输出的 80%；不同损耗场景同时要求原始输出与公平分配下理想有效到货达到各自理论值的 80%，避免只比较份额而漏掉吞吐下降。
10. 规划预算测试把每步工作上限压到 2，逐步检查实际工作计数不超限，同时要求所有可达目标最终获得供给。工程排队不能误记能量损失，已经开始的真实故障等待也不能被全网排队冻结。

## 独立审查已提出的问题

- 新到中继批次的正常输出冷却曾与故障等待共用时间判断，会在超时短于输出间隔时误淘汰。已向能源开发提出，并补专门回归测试。
- 已经滞留的批次部分发送后，留存片可能重新获得一个不计时的输出间隔。已提出独立滞留状态建议，并补拆分回归测试。
- 过期结算若在本步发送之后，可能让到期批次靠修复或改道逃避已经过去的滞留时间。主负责人提出此边界，测试已覆盖。
- 备用路线如果只过滤满缓存，会漏掉“缓存未满，但持续错失输出机会”的拥堵中继。已增加独立回归场景，保持最终目标不变，要求源头可以选更高损耗的直达路线。
- 共享中继的已分配批次与重新分配批次曾使用不一致的出口额度结算；优化回归暴露份额偏差。无备用路线时，把软拥堵当作绝对禁入也会导致管线反复断流。最终版本统一中继出口调度，并在容量允许且没有可行备用路线时保留基础路线；相关公平性与吞吐回归均已通过。

以上行为的通过结论限于本测试集及其明确的窗口、参数和误差范围，不等同于所有拓扑均已证明公平。

## 已知边界与其他验证责任

- 中继输出的量化尾数仍可能导致局部额度提前补充：当剩余原始输出不足以形成 1 单位有效到货时，“本次输出机会用完”与“本轮额度用完”尚有进一步区分空间。能源开发在同场景的独立测量中报告近端与远端到货比约 1.04746，处于原定 5% 范围内但接近上限；下一阶段应保留原断言，专项验证不同量子、输出量及损耗组合的长期偏差。
- 全部 EditMode 测试已由 Unity 实际执行通过。项目完整导入与 Console 状态、其他程序集以及构建检查由主负责人的集成验证记录承担，不能仅凭本报告的测试通过推定。
- 场景和 Prefab 的引用完整性、运行期不生成 UI 控件、实际点击与键盘操作。
- 100、400、1600 建筑下的图密度、模拟耗时、分配量、内存与改路响应测量。
- Unity 表现性能、Windows 构建和实际启动。
- 极端长期新建与出售、资源等待环，以及多源多瓶颈公平性的更多专项压力场景。

## 实现边界与主要决策

`Defend.Simulation` 不引用 UnityEngine。世界负责命令、占格、费用和建筑生命周期；能源模块负责路径、调度、批次、预约和数量账目。Unity 适配层负责输入、Prefab 和显示，唯一场景入口显式组装世界。Editor 工具只负责制作及迁移持久化资产。

逻辑默认 20 Hz，能量使用整数最小单位，1000 单位为 1 点。到货集合复用 .NET SortedSet，能源显示复用 Unity ObjectPool。路径采用低损耗搜索、按终端共享的反向路径缓存与有预算的跨步求解；供应候选和基础路线跨步复用，成交时重新核对动态容量。访问历史采用不可变父链，禁止同一批次重新进入已经实际访问过的建筑。已失去实际批次持有者的历史查询会取消，正常轮询延迟不会触发撤销。

优先级权重只对最终用能建筑生效，以有效到货计费。缓存先自用，有缺口再补；中继的所有目标共享同一出口额度和间隔。旧能量可以改目标、改路径，但不清除访问历史或累计滞留时间。正常飞行不增加滞留，持续拥堵和断路会增加滞留。

移动保留建筑内部储能与身份，取消发往旧位置的未完成接收；摧毁和出售损失建筑内部储能。核心护盾容量有限，白盒暂定 1 点能量吸收 1 点伤害。波次尚未实现，能源代码不读取波次状态。

## 规模测试

测试器位于 `Tools/Unity/WhiteboxValidation.cs`。最终调用 `MeasureBounded(count, 200, 200, 45)`，先预热 200 步再测量 200 步，三组均完成请求，未触发 45 秒墙钟上限。预热不保证已经达到稳定状态。合成场景为密集方阵：四分之一反应堆、二分之一中继、四分之一炮塔，半径 7 格；每个炮塔每步需求 1000 最小单位。单组总逻辑时长约 20 秒。

| 建筑数 | 有向连接数 | 单步 p50 / p95 / 最大值（毫秒） | 测量期消费 / 配置需求 | 结束时曾获能消费者 | 批次峰值 |
| ---: | ---: | --- | --- | --- | ---: |
| 100 | 4,072 | 25.008 / 42.596 / 90.464 | 4,629,091 / 5,000,000，92.6% | 25 / 25 | 537 |
| 400 | 24,166 | 86.353 / 126.681 / 230.408 | 13,684,360 / 20,000,000，68.4% | 100 / 100 | 10,826 |
| 1600 | 114,126 | 39.334 / 120.452 / 245.682 | 28,060,241 / 80,000,000，35.1% | 363 / 400 | 11,797 |

三组守恒差额均为 0。初始化耗时分别为 12.230、91.499、119.637 毫秒；预热最大单步分别为 105.001、255.052、104.341 毫秒。最终待规划数分别为 981、2148、2495。原始数据为 `performance-100-final.json`、`performance-400-final.json`、`performance-1600-final.json`。

**400 和 1600 的高密度场景未达到默认 20 Hz 所需的单步预算，且供给不足。** 1600 场景的测量窗口内还有 37 个消费者没有收到能量；它的中位耗时比 400 更低，不能解读为更高规模更快。100 场景虽然大部分需求得到满足，但仍有尖峰和规划积压，也不构成完整游戏 60 FPS 保证。

此前已经修复重复全图寻路、每步重新扫描全供应者及微小残片误封锁中继的问题。供应候选缓存使相同 400 建筑窗口的消费量从约 335 万提高到约 1368 万，同时暴露真实批次、历史查询和动态拥堵重规划的成本。下一阶段需针对这些热点做 Profiler 分析、失效范围缩小、批次规模控制和更长时间的公平性验证，不能只提高工作预算或继续增加内容。当前玩法验收范围是默认八建筑的交互白盒。

Unity 当前线程分配计数接口的探测结果不可用，数据记为 `null`；不能据此声称零分配。此测试只测 Editor 内纯模拟，不包含完整玩家帧、图形开销、内存长期曲线或特定目标硬件认证。

共同中继不同损耗的公平性测试保持原 5% 容差。量化尾数和出口轮次边界仍需更广的参数组合验证；当前 47 项通过不代表所有复杂拓扑均已证明公平。未完成跨平台确定性、长期频繁建售、内存增长及完整敌人战斗验证。

## 工程交付约束

场景、Prefab、配置和脚本均带 Unity 元数据。已有用户改动保留，不重置工作区，不改变已有 SampleScene 的构建场景列表，不提交或推送。构建显式指定本次开发场景。首次制作工具只创建缺失资产，已有场景会直接打开，避免覆盖团队手工编辑。

Unity 首次构建自动持久化了 DefaultVolumeProfile、PC_RPAsset、URP 全局设置、GraphicsSettings 与 URPProjectSettings 的当前版本字段、运行期资源列表和着色器预筛选结果，保留这些构建迁移。构建时 Performance Test 包生成的 Resources 临时文件已由该包自行清理。与本任务无关的 UnityConnect 开关恢复到本轮开始前的关闭状态。

原始命令证据保存在被 Git 忽略的 `Logs/WhiteboxValidation`；报告与使用说明属于可版本控制的工程文档。复现测试见使用说明和测试矩阵 `Docs/Validation/PhaseOneWhiteboxTests.md`。

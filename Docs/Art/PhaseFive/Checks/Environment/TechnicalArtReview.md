# 第五阶段模型技术美术复核

日期：2026-10-10。范围：只读复核十三份单体 JSON、建筑活动枢轴与占地记录、六种建筑的十二张 Blender 渲染、三种敌人的游戏视角渲染，以及现有表现层代码。未操作 Unity Editor，未改动模型或游戏表现代码。

结论：模型造型和 Blender 资产本体可接受，未发现需要重做的形体或已知几何错误。Unity 前向转换和一米间距下的相邻遮挡需要独立验证；游戏接入还必须处理旧 EnemyView 的缩放与整渲染器染色。这些验证层次不能互相代替。

## 必须修复或补证的项目

1. **以 Unity 可直接使用的 Prefab 交付前，修正前向与活动节点轴向。** 主负责人报告原始 FBX 在 Unity 实测前向是 -Z，而目标为 +Z。因此单体 JSON 的 Blender 再导入通过不代表 Unity 前向通过。主负责人正在生成统一 +Z 前向、Y 轴转向、节点局部旋转 0 与缩放 1 的专用 Prefab 和转换网格。本审查不把正在执行的修正记为已通过；最终状态以主负责人后续 Unity 直接字段与检视结果为准。应复核所有模型的 ForwardReference、炮口、后坐节点、四个足部枢轴及重装撞击枢轴，不能只旋转外层显示对象而遗漏活动节点语义。
2. **宣称相邻建筑无遮挡前，补充中心间距 1 米的约 70 度检视。** 独立单体图能证明自身可辨识，无法证明紧邻摆放的遮挡情况。中继器高 1.165 米，在 70 度俯视下高度对应的地面等效投影位移约为 `1.165 / tan(70°) = 0.424 米`。这不是已发现遮挡的结论，而是说明高度仍会造成屏幕投影偏移。应在独立检视场景放置反应堆、中继器与三种低炮塔的相邻小组，检查炮口和顶面识别特征；不改第四阶段关卡。

## 顶视辨识与一格包络：可接受，但保留相邻视图验证

已实际查看全部十二张建筑渲染：

- 反应堆：中央能源舱与两侧散热体构成高、宽、实的轮廓，70 度视图仍能看到前部青色舱体。
- 中继器：细柱加中空环，孔洞与支撑在70度视图保留，与反应堆、范围炮可区分。
- 连射炮：两根分离细管形成明确双管特征；近景炮口凹部可见。
- 重击炮：单根粗管、宽肩与后坐轨组成较重轮廓，与连射炮区分明确。
- 范围炮：低矮分段外环和中央发射器形成实心圆形顶面，不与中继器的高位空环混淆。
- 核心：方形顶舱与四角护罩使其在相同灰白材质下仍有独立轮廓。

三种敌人的游戏视角也已查看：四足、狭长低楔形、宽履带撞角的主轮廓清楚，橙色敌方标记与青色建筑能源可区分。

`Buildings/BuildingMotionAndFootprint.json` 直接记录六种建筑的静止结构边长在 0.72—0.88 米内，均满足一格底座约定。现有六种 PhaseThree 建筑定义的 `width` 与 `depth` 也均为 1，模型制作没有据概念图扩大占地。

连射炮和重击炮全转角运动部分最大水平半径分别为 0.527680 米与 0.530118 米，超出半格边界最多约 2.8 厘米与 3.0 厘米；范围炮为 0.405000 米。两种炮管的小幅伸出符合既定造型约定。该水平包络不等于相邻建筑在屏幕投影上完全不遮挡，也不证明任意两根对向炮管不会相互接近。

三个炮塔在 Blender 内存中绕转台转动 90 度时炮口跟随，沿后坐节点移动 0.04 米时炮口跟随，相关直接检查通过。这证明 Blender 层级和枢轴关系；转换后的 Unity 本地轴仍须单独验证。

## 渲染成本：白盒可接受，接入时优先实测

StandardEnemy 的五个网格保留了主体和四条机械足，符合活动分件要求；每条腿三种材质，导致每实例 15 个材质槽。它是首要的批量敌人渲染成本关注项。举例而言，100 个此类实例对应 500 个渲染网格、1500 个材质槽使用位置和 60000 个三角面；这些数量不能直接当作最终绘制调用数或帧时间。

三种炮塔保留底座、转台、发射组件，分别有 9、10、10 个材质槽使用位置。此次不应仅为降低静态网格数量合并掉活动分件。后续若实测显示提交成本成为瓶颈，可评估每分件使用更少材质、合适的共享着色方案或其他批处理方式；本轮没有运行性能或长时间验收，也不据面数宣称性能已经通过。

## 后续实际游戏接入前必须处理

1. **取消或适配旧的按敌人种类二次缩放。** `Assets/Defend/Scripts/Unity/Presentation/EnemyView.cs:50` 目前让重装根节点缩放为 `(1.5, 1.25, 1.5)`，快速敌人缩放为 `(0.65, 0.7, 0.65)`。新模型已经按最终世界尺寸制作，直接套用后，重装会变为约 `1.56 × 1.74 × 0.611 米`（宽 × 长 × 高），快速敌人会变为约 `0.325 × 0.520 × 0.178 米`。普通敌人不受此分支额外缩放。应在表现层建立明确的原始尺寸约定，避免额外父级反向缩放掩盖问题。
2. **避免旧反馈染色覆盖整套敌方材质。** `EnemyView.cs:56-58` 仍按敌人种类选择黄、紫、红色，并用单一 Renderer 的 MaterialPropertyBlock 覆盖 `_BaseColor`。把新主体渲染器直接接给 `bodyRenderer` 会覆盖该渲染器所有材质槽的底色，破坏橙色敌方标记与深色机械结构；四条独立腿又不会同时获得同一反馈。建筑 `BuildingView.cs:42-49` 也对单个反馈渲染器设置颜色。后续应明确反馈作用范围，保留共享材质的基础配色。
3. **补齐表现组件引用后再接入。** EnemyView 的 `healthFill` 与 BuildingView 的选择、能量条、销毁标识等引用不属于本轮纯模型 Prefab。缺少这些引用时不能把模型 Prefab 直接替代现有可玩 Prefab。绑定 `facingRoot` 时使用已经统一前向的视觉根节点；步态、后坐与撞击动作按预留分件逐项接入，本轮未实现这些行为。
4. **保持地图与模拟边界。** 环境模型、机械足、履带、炮管的视觉边界不应反过来改写既有一格建筑占地、导航通道、攻击范围或碰撞结算。地面主表面为根节点上方 0.078 米，地编时可按主表面下沉；检修盖最高为 0.086 米。
